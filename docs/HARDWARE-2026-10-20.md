## Verified stock implementation

The page constructs:

```javascript
socket = new WebSocket('ws://' + window.location.host + ':8000');
socket.binaryType = "arraybuffer";
```

The binary send function parses hex pairs into a `Uint8Array` and calls:

```javascript
socket.send(sendArray);
```

The receive function handles `ArrayBuffer` by wrapping it in a `Uint8Array`.

## UART configuration after restart

The W610 configuration page reported:

- Transparent mode
- 38400 baud
- 7 data bits
- Even parity
- 1 stop bit
- Flow control disabled

This confirms the stored W610 UART configuration is `38400 7E1`.

## DB9 pins 2–3 loopback

With transmit and receive connected directly, the real TNCweb browser sent two patterns through the W610:

1. Control-heavy sample:

   ```text
   00 01 02 03 04 06 11 13 15 17 1B 7F 41 42 43 0D 0A
   ```

2. Every 7-bit value:

   ```text
   00 01 02 ... 7E 7F
   ```

Both transmitted and received traces matched the expected bytes exactly. The full 128-byte range returned in one WebSocket message.

## FE1 directory verification

The live TNC requested the external directory with:

```text
13 1B 11 4F 20 44 0D 0A
```

The first accepted test used the FE401-style line:

```text
H100                   3       5
```

The TNC displayed this as `100.H` and returned `<EOT>` after the response's `<ETX>`.

The final directory response contained all eight sample files using `H` plus the basename mapping:

```text
HCASEBOTT
HCASEBTAP
HCASEFSLO
HCASEMAIN
HCASETAP
HCASETOP
HCASETOPF
HCBERNG37
```

All eight programs were visibly listed on the TNC.

After selecting the test program, the TNC sent:

```text
01 48 31 30 30 45 17 2A 03 04
```

This is a request for `H100` using the BCC-protected file header and was recorded for the next implementation stage.

Selecting the real `CASEBOTT.H` entry produced:

```text
01 48 43 41 53 45 42 4F 54 54 45 17 02
```

This is `<SOH> HCASEBOTT E <ETB> <STX>`, where `0x02` occupies the BCC position. It confirms that the displayed `CASEBOTT.H` is mapped to `HCASEBOTT` internally.

The port, UART, browser transport, byte integrity, directory listing, and filename mapping are now hardware-verified.
