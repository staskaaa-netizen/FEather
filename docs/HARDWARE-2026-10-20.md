## Verified stock implementation

The page constructs:

```javascript
socket = new WebSocket('ws://' + window.location.host + ':8000');
socket.binaryType = "arraybuffer";
```

The binary send function parses hex pairs into a `Uint8Array` and calls:

```javascript
socket.send(sendArray);
```

The receive function handles `ArrayBuffer` by wrapping it in a `Uint8Array`.

## FE1 directory verification

The live TNC requested the external directory with:

```text
13 1B 11 4F 20 44 0D 0A
```

The first accepted test used the FE401-style line:

```text
H100                   3       5
```

The TNC displayed this as `100.H` and returned `<EOT>` after the response's `<ETX>`.

The final directory response contained all eight sample files using `H` plus the basename mapping:

```text
HCASEBOTT
HCASEBTAP
HCASEFSLO
HCASEMAIN
HCASETAP
HCASETOP
HCASETOPF
HCBERNG37
```

All eight programs were visibly listed on the TNC.

After selecting the test program, the TNC sent:

```text
01 48 31 30 30 45 17 2A 03 04
```

This is a request for `H100` using the BCC-protected file header and was recorded for the next implementation stage.

Selecting the real `CASEBOTT.H` entry produced:

```text
01 48 43 41 53 45 42 4F 54 54 45 17 02
```

This is `<SOH> HCASEBOTT E <ETB> <STX>`, where `0x02` occupies the BCC position. It confirms that the displayed `CASEBOTT.H` is mapped to `HCASEBOTT` internally.

## FE1 selected-file retrieval

The browser responded to the selected-file headers with ACK and transferred both `CASEBOTT.H` and `CASEBTAP.H` as individual BCC-protected line blocks. The TNC acknowledged every block. No NAK or timeout occurred.

Representative trace:

```text
RX 06
TX 02 31 37 20 20 4C 20 4D 39 39 17 32 11
RX 06
```

The final lines completed similarly. After the last ACK, the browser sent `03` (ETX), and the TNC replied `04` (EOT), confirming successful program retrieval.

The port, UART, browser transport, byte integrity, directory listing, filename mapping, and selected-program retrieval are now hardware-verified.

## TNC-to-browser transfer

The TNC uploaded two programs to the browser:

- `CRANFINS.H`: 16 line blocks
- `CRKFIN.H`: 34 line blocks

Each file began with an FE1 `A` header. The browser validated the header and every block BCC, returned ACK after each valid block, and committed both files only after ETX/EOT.

The files were stored in IndexedDB and were included in the next external directory response. This direction is hardware-verified.

## TNC-requested deletion

The TNC requested deletion with:

```text
13 1B 11 44 20 H C A S E B O T T 0D 0A
```

The browser deleted the corresponding IndexedDB record, rebuilt the external directory, and sent it with ETX. The TNC returned EOT.

The same complete operation succeeded for `HCBERNG37`. Both files disappeared from the refreshed TNC external-directory list.
